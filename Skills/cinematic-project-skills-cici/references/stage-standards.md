# Essential stage standards

These are the Cici workflow's production conventions, not a claim of industry certification. They standardize the evidence required to move work forward. They do not prescribe one creative method or add permission requests to every stage.

## Stage contracts

| Stage / responsibility | Entry | Required output | Exit evidence | Next handoff |
|---|---|---|---|---|
| 01 Development / writer and director | Brief, source and existing decisions | Audience promise, treatment or script, scene progression, constraints | Intended experience and essential events are clear; timing is plausible; consequential assumptions identified | Versioned story and open creative choices |
| 02 Direction / director | Current story and accepted look | Director's treatment: interpretation, audience viewpoint, performance, staging, image/sound/time principles | Major choices describe observable effects; scene turns have carriers; no conflict with locked facts | Selected directing decisions and scene states |
| 03 Preparation / director, design and producer | Selected direction and practical constraints | Beat-to-shot coverage, reference map, continuity, sound cues, job/dependency plan and budget | Every essential beat has coverage; references fit required views/actions; dependencies and cost are feasible | Versioned production package, readiness and authorization recorded separately |
| 04 Production / execution and continuity | Ready package and applicable permission | Original outputs, job/take records, inspection notes, selects and repair queue | Required coverage is available and inspected, or missing material is explicitly marked for the assembly | Selected sources, ranges, sound and continuity notes |
| 05 Editorial / editor and director | Available footage and sound | Playable assembly, timestamped review, revised cut and picture-lock record | Full story reviewed in context; blocking issues resolved or explicitly deferred; timing/version frozen for finishing | Locked edit and remaining finishing work |
| 06 Finishing and delivery / post-production | Selected edit and destination requirements | Finished sound/color/titles/captions as required, actual export, QA and provenance | Actual deliverable inspected; limitations disclosed; user acceptance recorded only if received | Delivery file, editable project where requested, next action or closeout |

Sound planning begins in stages 01–02, source tests can occur in preparation under existing authorization, and assembly begins while production continues. These are dependencies, not six isolated departments waiting in sequence.

## Machine-readable handoffs

Use `P1` through `P6` for the six rows above in `project-state.json`. Record `applicable`, input/output IDs, status, exit-check IDs and next action. A stage outside the requested scope needs a reason, not a fictitious completion. A draft-only project does not need unrequested formal generation.

Treat work state, dependency readiness, operation authorization and inspection coverage as separate dimensions. A passed stage needs actual outputs and explicit exit evidence; a file alone is insufficient. Unperformed playback/listening remains unknown even when the user likes the cut.

Run the shared project checker at the events defined in the project-control contract. It verifies record consistency, not artistic success. Preserve the owner's actual review gates: internal P1-P6 handoffs do not add six user approvals or remove required specialist approvals.

Show completed tasks, current artifacts, blockers and next actions rather than an unweighted completion percentage. If a check fails, identify the affected task chain and continue independent authorized work.

## Essential decisions versus optional machinery

Always establish the audience goal, scene/sequence purpose, selected visual and performance approach, coverage and continuity, resource limits, actual review evidence, and honest delivery state. On a tiny film, one document can contain all of them.

Use storyboards, keyframes, animatics, spatial diagrams, camera tests, multi-view assets, live rehearsals, and pilot clips when they resolve a named uncertainty. Do not require all of them automatically. An animatic tests timing and visual order; it is not motion/performance evidence. A motion test answers only the tested conditions.

For live-action add practical crew/location/call-sheet and backup information. For a series maintain shared canon and episode-specific states. Neither changes the core directing deliverables.

## Baselines and changes

A baseline is a selected artifact/version, not a claim of user approval. Record who selected it and which decisions it covers. Existing explicit user decisions remain valid. Human decisions are required where the user reserved selection or acceptance; routine internal readiness checks proceed without repeated permission.

Changes to story, assets, selected takes, sound, duration or settings identify affected successors. Mark only those successors `needs-recheck`; keep unrelated work. New costs must remain inside authorization. Reopening picture lock reopens affected sync, captions, music and exports.

A full-project handoff contains: current phase; latest artifact versions; selected decisions; missing items/defects; next owner/action; remaining authorization/resources. A handoff must be usable without rereading chat history.

## Release criteria

Do not call a generated batch a completed film. A delivered review cut may remain unaccepted. A passing export check cannot compensate for missing story coverage or unintelligible dialogue. Distinguish self-review, real viewer feedback, tool checks and user acceptance.

Reserve full-project finalization for actual deliverables, evidence and known limitations. Stop only affected work for a missing input, permission, tool capability or resource limit; continue independent useful work.
