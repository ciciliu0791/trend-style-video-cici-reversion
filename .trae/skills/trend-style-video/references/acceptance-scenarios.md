# Skill Acceptance Scenarios

Use these as tabletop checks when maintaining the skill. They are expected decisions, not evidence of a real generated production or measured improvement. Do not call paid services to run them.

| Scenario | Expected behavior | Failure to prevent |
|---|---|---|
| "Make something with this video's mood, using my own cast" | Extract verified mechanisms; resolve remake/rewrite if the story intent is still ambiguous, then develop the chosen direction | Silently choosing a new plot merely because the request entered through Trend |
| Reference URL cannot be inspected | Mark evidence missing; request a file or offer a clearly labeled description-led concept | Invented source cuts, audio or current popularity |
| Adopted cast/look, five proposed shots, standing image permission | Reuse anchors; create only necessary images; batch independent selection with the video package | Five compulsory new keyframes and five generation-permission stops |
| Frame B must use the user's selected A | Wait for A selection only for B-dependent work; continue independent planning | Generating speculative B or treating budget permission as A approval |
| A candidate has a broken contact point but acceptable palette | Flag affected geometry; propose bounded targeted repair | Reworking the adopted style or silently submitting the defective candidate |
| Exact three-job package approved; pilot succeeds | Continue unchanged approved jobs and assemble a complete cut | A fresh confirmation after every successful clip |
| Pilot fails and invalidates one dependent job | Pause that job, propose specific changed inputs; retain independent approvals | Entire project restart or unapproved retry |
| First/last-frame mode unsupported | Explain limitation and propose a supported mode or deliberate cut for approval | Calling generic references frame-locked endpoints |
| Manyue project; draft vs formal production | Follow current workspace stage rules: dynamic draft 2.5/480p; formal production uses approved specs, otherwise earlier Fast preference | Applying a tool default, treating production draft as API `draft=true`, or importing Manyue conventions into other casts |
| "Add a short hold at the end of S1" | Inspect current edit, make local hold, check affected joins/audio, version export | New generation, altered user trims, whole-project approval restart |
| User supplies music | Inspect available duration and musical evidence; integrate and disclose unheard dimensions | Claiming musical QA from loudness statistics |
| Export requested; current source matches existing MP4 manifest | Verify and deliver existing correct artifact | Unnecessary rerender or returning only a preview |
| Budget covers draft only; user likes the cut | Ask only for any uncovered final production scope; offer honest qualifying reuse | Treating praise as permission for new 1080p generation |
| Final reviewed version accepted; later edits alter it | Preserve prior acceptance; label new export awaiting acceptance | Transferring acceptance to unseen bytes |
| Another tool requires explicit confirmation | Satisfy its requirement using valid shared evidence when possible | Treating "two checkpoints" as permission to bypass mandatory confirmation |
| Resume with a known task ID and downloaded original | Verify/recover recorded work and continue the next dependency | Duplicate submissions, lost approvals or rereading all history |

## User-Facing Review Regression Scenarios

Tabletop-check these decisions against the main workflow, creative-development and production-and-review instructions. They validate the intended review behavior, not actual generation quality.

| ID | Situation | Required decision and rationale |
|---|---|---|
| R1 | Every job has request.json, but the review only shows thumbnails and prompt hashes | Incomplete review delivery. Expand full image/video prompts, ordered references and settings beside their results; machine traceability is not user-readable review |
| R2 | Standing image permission, selected look, three independent new compositions | Show exact image cards, then execute the scoped batch without a new per-image spending question; preserve dependent visual selection requirements |
| R3 | Video summary is unchanged but the compiled request appends a new restriction | Compare compiled text, roles and parameters; pause the affected submission for exact-input review rather than assuming the summary covers it |
| R4 | An old generated image never had a readable prompt page | Disclose the actual submitted prompt retrospectively, preserving request and approval bytes; never label it reviewed before submission |
| R5 | Every shot meets a technical checklist, but the ending repeats prior information | Reopen the whole-film creative finding before commissioning images; trace viewer discovery and source mechanism instead of adding more gates |
| R6 | Quiet reference or an emotional reaction has little physical movement | Preserve its selected trigger, visible response, pause and consequence; do not import Manyue action quotas or add arbitrary walking |
| R7 | Pilot has a crop defect; a different take's critical contact geometry remains uninspected | Crop may be editorially repairable, but unverified dependent geometry cannot be treated as proven; continue only independent covered work and label draft defects |
| R8 | Draft assembled and decoded successfully, listening unavailable | Deliver the actual cut with exact intervals/questions/reviewer for missing listening; do not mark the listening check passed or waived for convenience |
| R9 | User likes the performance, asks only to remove a few bad frames | Trim within scope, check joins and sound, version the export; new paid inputs need affected-job approval, not an automatic formal-generation ladder |
| R10 | Five creative deliverables introduced while shared state uses P1-P6 | Map deliverables onto existing stages without new required schema keys, second history or five approval stops; retain two planned checkpoints and exact-export acceptance |
| R11 | Silent motion draft authorized; full film needs a track not yet supplied | Show the silent cut as scoped work and keep the sound plan open; do not generate unauthorized audio or declare the final soundtrack complete |
| R12 | Adopted low-resolution motion meets the creative goal but not the locked source spec | Propose explicit qualifying reuse or authorized upgrade; disclose native/output sizes, never infer a quality exception from praise |

## Maintenance Checks

- Validate frontmatter, directory/name equality, non-empty body and all local Markdown links.
- Do not change source-reference skills without explicit scope; for an authorized coordinated update, verify only approved files changed. Report legacy registration/name exceptions rather than silently migrating or claiming a universal pass.
- Confirm that selection, spending and QA remain separate in all scenarios.
- Confirm image count is driven by uncertainty, not a universal per-shot requirement.
- Confirm full image prompts are readable before image calls and full video prompts before video submission, including compiled shared constraints and appended corrections.
- Confirm the template contains actual full-text prompt blocks, not only directing fields or request links, and preserves the shared progress markers.
- Confirm whole-film findings precede image commissioning and link source mechanisms to audience consequences, revisions and unresolved tests.
- Confirm five creative deliverables do not add gates, shared-state fields or Manyue-specific conventions to other casts.
- Confirm story/camera development precedes image commissioning.
- Confirm generated services are not invoked by skill creation or these tests.
- Report structural/tabletop validation separately from real production evaluation.
- Check actual rendered prompts, not just analysis/rationale fields. Keep existing JSON contracts compatible; no new mandatory schema keys for these checks.
- Do not imply that a regex/keyword check validates creative reasoning; pair structural tests with the explicit tabletop decisions above.
- Run the Cici standard-library offline tests with `PYTHONDONTWRITEBYTECODE=1`; keep temporary fixtures outside the deliverable tree. Validate shared state references and checker CLI behavior, including its blocked exit code.
- Verify that shared-control updates remain within authorized files; do not alter global tool skills, other workflows or real production approvals as part of these tests.
- Verify both workspace entries point to the same actual analysis prompt and adaptation-choice contract; do not merge provider adapters or duplicate the shared analysis.
- Confirm the directory-aligned workspace name does not rewrite historical `viral-remake` owner labels or confuse them with the global skill.
